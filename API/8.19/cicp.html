Using > Processing CICP images [src]

CICP is a relatively new way of tagging an image with information about how colour values should be displayed. It serves roughly the same purpose as an ICC profile, but is very small, simple, and is designed for HDR.

libvips supports loading and saving images with CICP tags from AVIF, JXL, and PNG images, it supports loading and saving these images to UltraHDR formats like JPG with automatic conversion of tags, and it supports save to ICC-only formats with automatic profile generation. libvips also supports generating and modifying CICP tags programmatically, including support for computing some image properties, such as target illumination.

As with other colour tagging systems, like ICC and UtraHDR, there are two main paths for CICP images. You can leave them as 16-bit unsigned integer with CICP tags and rely on automatic conversion by savers, or you can convert them to full HDR images in scRGB space and do you own colour handling. Doing your own handling will usually be slower, but give more control.

Native numeric format with CICP tagging

CICP images are 16-bit unsigned integers, with extra metadata for colour interpretation.

The JPEG saver has seen the CICP tags and generated an UltraHDR image automatically using libultrahdr. Additionally, it has used the CICP tags to make a synthetic ICC profile which should preserve CICP colour information.

This might now display as HDR, depending on your screen and browser:

You can also convert to AVIF, of course. Since AVIF supports CICP, this is much simpler.

$ vips copy cicp-car-small.png cicp-car-small.avif

Again, the appearance will depend on your browser and display. On SDR displays, these two versions of the original probably won’t match well, since the UltraHDR image has been tonemapped, whereas the AVIF will display the SDR component of the CICP data.

High-level libvips operations

The vips_thumbnail() operation knows about CICP tags and will use them automatically for colour processing with the linear and output-profile options.

À la carte processing

So the image has been converted to linear float, with the range 0-1 for black to paper white. Values above 1.0 (the maximum for this image is 9.77, for example) represent HDR pixels.

The ICC profile and the CICP metadata are untouched. If you convert back the other way with vips_scRGB2CICP(), this metadata is used to generate the inverse transform.

You can use the libvips metadata API (vips_image_get_double() and friends) to get and set the various HDR fields and change the presentation.

You can use vips_percent_lum() to compute new values for clli-max-content-light-level and clli-max-frame-average-light-level efficiently.
